### P1

#### 5. スキーマ検証をより深く(既知/未知の二段階)

`ThreadItemSchema`が`type`と`id`しか検証していないため、例えば`agentMessage.text`が欠けていても境界検証を通過してしまう。

単純な`discriminatedUnion`だけにすると未知のitem typeを受け付けなくなるため、**既知型は詳細検証、未知型はid/typeのみで汎用表示**という二段階にする。`type`を先に見て対応スキーマを選び、既知型の不正データを未知型へフォールバックさせないようにする。

```ts
const KnownThreadItemSchema = z.discriminatedUnion("type", [
  AgentMessageSchema,
  ReasoningSchema,
  CommandExecutionSchema,
  FileChangeSchema,
  UserMessageSchema,
]);

const UnknownThreadItemSchema = z.object({ type: z.string(), id: z.string() }).passthrough();
```

まだ型アサーションが残っている箇所(優先度は主要turn系より低い):
- `thread/tokenUsage/updated`
- `model/list`
- `account/rateLimits/read`
- `gitDiffToRemote`の結果

#### 6. プロジェクト探索の上限・タイムアウト・打ち切り表示

`list_directories`(`find`コマンド)は深さ制限のみで件数上限がない。対応順序:

```text
1. 最大件数
2. タイムアウト
3. 結果が打ち切られたことをUI表示（黙って打ち切らない）
4. キャンセル
5. .gitを持つディレクトリだけ表示するオプション（既定値にはしない）
```

最大件数だけ設定して黙って打ち切ると、ユーザーに「全件か一部か」が伝わらないため、戻り値に打ち切りフラグを含める。

```rust
struct DirectorySearchResult {
    directories: Vec<String>,
    truncated: bool,
}
```

`.git`限定オプションは、未初期化の新規プロジェクトが一覧から消えてしまうため、既定ではなく明示的なオプションとして提供する。

### P2

#### 8. `-32001`(Server overloaded)の再試行

現状でもエラー表示はできるため機能は壊れておらず、再試行の実装ミスは二重実行の危険を伴う。優先度は中。

前提として、`RpcFailure`へJSON-RPCのcode/dataを保持できるようにする必要がある(現状は`server_rejected`がエラー全体を文字列化しているだけで、`message`の文字列検索で`-32001`を判定するのは不安全)。

```rust
pub struct RpcFailure {
    pub kind: RpcFailureKind,
    pub message: String,
    pub code: Option<i64>,
    pub data: Option<serde_json::Value>,
}
```

再試行してよいRPCは許可リスト(ブロックリストではない)で管理する。`thread/list`・`thread/read`・`model/list`・`account/rateLimits/read`は対象、`thread/start`・`turn/start`・承認応答・`thread/name/set`は対象外(二重実行につながるため)。
