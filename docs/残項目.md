## 未対応

### 1. テスト基盤の整備(優先度: 高)

現状、Rust側・TypeScript側ともに自動テストが存在しない。特に以下は今回のレビューで安全性の根拠とした部分であり、将来の変更で壊れても気づけない。

**RpcFailure/journalの5ケース(最優先)**
- `connection_lost` → journal保持
- `response_timeout` → journal保持
- `write_failed` → journal削除
- `server_rejected` → journal削除
- `internal_error` → journal保持(許可リスト方式であることの確認)

**Rust側**
- JSON-RPCメッセージルーティング(`route()`の4分岐: server-request/notification/response/contamination)
- Windows→WSLパス変換(`windows_path_to_wsl`)
- UNCパス変換(`open_in_explorer`)
- `net use`出力解析(`resolve_drive_mapping`)
- 非JSON contaminationの検知
- pending requestのtimeout

**TypeScript側**
- 承認decisionのラベル変換(`decisionLabel`)
- notificationのreducerロジック(`switch (method)`内の各分岐)
- deltaバッチ更新(`scheduleFlush`)
- スレッドフィルタリング(`filteredCommands`等)
- journal調停ロジック(`reconcileJournal`)

### 2. `-32001`(Server overloaded)の再試行

仕様にあった指数バックオフ＋ジッターでの再試行が未実装。副作用のないRPCのみに限定して適用すること。

- 再試行してよい: `thread/list`、`thread/read`、`model/list`、`account/rateLimits/read`
- 再試行してはいけない: `thread/start`、`turn/start`、承認応答、`thread/name/set`(二重実行につながるため)

### 3. `App.tsx`の分割

通信・thread管理・承認・diff・モデル・使用量・ドラッグ&ドロップ・スラッシュコマンドがすべて`App.tsx`に集中している(1000行超)。次の単位への分割が提案されている。

```text
hooks/useCodexConnection.ts
hooks/useCodexNotifications.ts
hooks/useThreads.ts
hooks/useTurn.ts
hooks/useApprovals.ts
hooks/useProjectDiscovery.ts
components/Sidebar.tsx
components/Transcript.tsx
components/Composer.tsx
components/ApprovalCard.tsx
components/DiffModal.tsx
components/UsagePanel.tsx
```

状態管理ライブラリの導入は不要、custom hookへの分離で十分との評価。

### 4. プロジェクト探索の規模制限

`list_directories`(`find`コマンド)は深さ制限のみで、件数上限がない。大きいディレクトリを探索ルートに指定すると全件を一括でメモリへ読み込む。

- 最大件数の上限
- タイムアウト
- キャンセル可能にする
- `.git`を持つディレクトリだけ表示するオプション

### 5. スキーマ検証をより深く

`ThreadItemSchema`が`type`と`id`しか検証しておらず、その後`as unknown as ThreadItem`でキャストして描画しているため、例えば`agentMessage.text`が欠けていても境界検証を通過してしまう。

`z.discriminatedUnion("type", [...])`で、実際に描画するitem型(`agentMessage`/`commandExecution`/`fileChange`/`reasoning`等)ごとに詳細スキーマを定義するのが次の段階。

また、以下にはまだ型アサーションが残っている(優先度は主要turn系より低い)。
- `thread/tokenUsage/updated`
- `model/list`
- `account/rateLimits/read`
- `gitDiffToRemote`の結果
